# 0004 GATT 电量读取(BLE)

**状态**:实现完成,待 BLE 设备到手验证

- `GattRules`(Core,3 测):0x180F/0x2A19 UUID 常量、电量字节解析(>100 视为脏)
- `GattBatteryReader`:FromIdAsync → 服务(Cached→Uncached)→ 特征(Cached→Uncached)→ ReadValueAsync(Uncached)

- 硬件到手验证:连接 BLE 设备 → dump.bat 看是否出现 `[GATT] … level=N`

# 0007 罗技 HID++(尽力而为)

**状态**:实现完成,无硬件验证,预计需要按真机日志校准

- `HidppRules`(Core,11 测):帧构建(feature/RAP)、错误帧(0x8x)、swId 匹配、root 协议解析、
  feature-set 枚举解析、三种电量响应解析(unified 0x1004 / legacy 0x1000 / RAP 寄存器 0x07)
- `HidppBatteryScanner`:
  - 厂商接口:0xFF00 usage 1/2(Unifying)+ 0xFF43 usage 0x2102(Bolt/Lightspeed)
  - 配对槽 1–5 逐个探测;2.0 走 root fn1 → feature-set 枚举找电池 feature(接口级缓存)→ 读;
    1.0 回退 RAP 0x07
  - 事务:CreateFeatureReport → Send → GetFeatureReportAsync(带 1.5s 超时,重试 3 次抗异步事件插队)
  - 每步 DebugLog;预计帧偏移可能需要按真机 dump 修正
- 注意:HID++ 槽位电量只在设备唤醒时可用,睡眠设备可能超时(参考实现同样如此)

# 0009 HID 0x85 电池页(通用)

**状态**:实现完成,待键鼠/接收器到手验证

- `HidReportRules`(Core,7 测):启发式解析——跳过 reportId,取最后一个 1–100 字节;0 视为哨兵不展示
- `HidBatteryScanner`:AQS 属性条件 `System.DeviceInterface.Hid.UsagePage:=133` 枚举 →
  HidDevice.FromIdAsync(Read) → GetInputReportAsync → dump 原始字节 + 解析
- ⚠️ 布局无统一标准:拿到真机 dump 后按实际报告收紧 `GuessBatteryPercent`
- BT 键鼠场景:Windows 若把电量挂 0x85,此路径与 AEP 属性互补(去重靠 catalog 同名合并)
